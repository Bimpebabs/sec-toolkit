# Style Guide

Rules for entries in the sec-toolkit README.

## Entry format

```markdown
* [Name](https://github.com/owner/repo) — One-sentence description. When to reach for it.
```

## Rules

1. **Name** — the project's canonical name, exactly as it appears on GitHub.
2. **URL** — the primary URL. Prefer the GitHub repo over a project website. Use `https://`.
3. **Em-dash** — ` — ` (space, em-dash, space) between the URL and the description.
4. **Description** — one sentence, present tense, no marketing language. Under 140 characters where possible.
5. **When to reach for it** — one short clause (5–12 words) giving the practitioner's take. This is the differentiator.
6. **Alphabetize** — entries within each section, case-insensitive.
7. **No emojis** in the description body.
8. **No marketing language** — avoid "best", "awesome", "amazing", "powerful", "cutting-edge".
9. **Dual-use tools** — add a one-line context note in italics: `*C2 framework. Use only in authorized engagements.*`
10. **Unmaintained tools** — add a one-line note in italics: `*Unmaintained since YYYY; still works for X.*`

## Section headers

Use sentence case. Example: `## Web Application Security`, not `## Web application security` or `## WEB APPLICATION SECURITY`.

## Sub-section headers

Use `###` for sub-sections within a top-level section. Example: `### Subdomain & DNS enumeration` under `## Reconnaissance & OSINT`.
